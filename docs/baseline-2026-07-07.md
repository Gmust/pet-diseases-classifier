## Torch evaluation

Command:

```bash
.venv/bin/python -m app.ml.evaluate \
  --backend torch \
  --model-dir models/transformer_model \
  --data data/owner_eval.parquet \
  --label-map data/label_map.json
```

Observed results:

- Top-1 accuracy: 0.770
- Top-3 accuracy: 0.953
- Weighted F1: 0.76
- Infectious and Parasitic Diseases recall: 0.34

The printed macro-F1 was 0.54, but the current evaluator includes zero-support classes that appeared only in predictions. This value is recorded for fidelity but MUST NOT be used as a release threshold. Evaluation must use an explicit required label set and fail when required classes have no support.

## Known baseline risks

- Raw softmax confidence is uncalibrated while runtime thresholds treat it as confidence.
- Model and data payloads have no immutable retrieval location or release manifest.
- A species-only wellness request can receive a positive wellness band despite minimal evidence.
- Unexpected inference exception text is returned to API clients.
- Chat does not enforce its documented final-user-message rule.
- Chat OpenAPI metadata contains an incorrect response example due to duplicate model configuration.
- README and ONNX deployment documentation disagree with current code and SAM defaults.
